# Architecture and timing contract

The selected workspace is D:\Fauxphonic App. Before work it contained the unchanged product specification and a graft/.cache directory, no Git repository or application. The user-supplied AGENTS instructions apply. No other parent/project AGENTS file was found. The new private remote is https://github.com/Lipton1010/Fauxphonic . The app's original working brand is Fauxphonic.

The native PySide6 Widgets process edits a version-1 JSON project and persists its local queue in SQLite. A single QProcess worker receives a small JSON request file, emits protocol-1 JSON Lines on stdout, and reserves stderr for diagnostics. No localhost server exists. Queue retries restart the entire render deterministically; stateful model checkpoint continuation is not claimed. A per-user application lock prevents two GUIs from rewriting the same queue. A Windows Job Object kills worker children when the worker exits unexpectedly.

The worker uses pinned FFmpeg/ffprobe executables with file/pipe protocols only. Each input explicitly selects one audio stream (ambiguous containers fail until an index is entered), decodes/resamples to 48 kHz disk-backed float W64, and optionally applies conservative high-pass/spectral DSP. Speech noise reduction requires the user-assigned speech role and mono; stereo music is bypassed. Channel layouts larger than stereo are rejected. No source file is overwritten or edited.

Mixing uses 65,536-frame float32 blocks. Offsets are nonnegative integer project samples, independent of file starts; original container start times are reported but not automatically interpreted as common clock timestamps. Mono maps equally to both channels if another track is stereo. Inputs are summed without implicit normalization; user gains and floating-point intermediates preserve headroom. There is no automatic alignment, time stretching, silence trim, speaker detection, or automixing. Frame counts are validated after final encoding.

Whole-program mastering uses FFmpeg two-pass loudnorm with LRA=50 (no requested range reduction), explicit 48 kHz output, measured first-pass parameters, and actual normalization mode in the report. The final WAV24/FLAC is decoded and measured independently. ±0.5 LU and +0.1 dBTP are the starting acceptance tolerances. Bypass has no loudness compliance claim; silence and sub-three-second clips are exceptions. Failed constraints prevent audio promotion. Integer dither is applied at final quantization only.

Scratch is conservatively estimated before rendering. Temporary intermediates are application-owned and removed on orderly completion/cancellation. Crash remnants remain recoverable rather than triggering broad deletion; no automatic cache eviction exists yet. Output reservation is Windows-exclusive and delete-on-close, including crashes. A source digest before/after rendering detects concurrent modification. JSON report and audio are individually atomically renamed, with the report first; these two files do not constitute a filesystem-wide transaction. A sudden process death between renames may leave an orphan report, which is never interpreted as completed audio.

Python package versions are fixed and hash-locked. PyInstaller produces separate GUI (no console) and worker executables in one shared folder. Models are deliberately absent from the distribution. CPU mode does not import GPU runtimes. The 24 GB development GPU cannot establish 16 GB compatibility.
